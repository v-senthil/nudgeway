# ADR 0006 — OpenAPI 3.1 as the source of truth

Status: Accepted (2026-09-03)

## Context

Hand-written handler signatures drift from the spec, request/response types get duplicated in three places (docs, server, client), and the frontend team's contract becomes tribal knowledge.

## Decision

- `internal/api/openapi/openapi.yaml` is the source of truth for every REST endpoint.
- Go server interfaces are generated by `oapi-codegen`.
- TS client is generated by `openapi-typescript` + `openapi-fetch`.
- All error responses use RFC 7807 (`application/problem+json`).
- CI runs `spectral lint` and `openapi-diff` — accidental breaking changes fail the build.

## Consequences

- Editing `openapi.yaml` is the first step of any API change; there is no other path.
- The frontend can consume typed client changes as soon as the spec is regenerated.
- Doc-drift is impossible: types come from the spec, and Scalar/Redoc renders from the same file.
